# Работа с git

## 1. Перед изменениями
1. `run_shell: git status --short` и `git branch --show-current` — понять состояние.
2. `git log --oneline -10` — стиль сообщений в проекте.
3. Если рабочее дерево грязное — не смешивай свои правки с чужими: сначала спроси пользователя.

## 2. Ветка и правки
- Новая работа — новая ветка: `git switch -c feature/краткое-имя`.
- Правки — маленькими шагами, после каждого логичного шага прогоняй тесты.
- Проверка своих изменений: `git diff`, `git diff --stat`.

## 3. Коммиты
- Один коммит = одна мысль. Сообщение в повелительном наклонении: `добавить экспорт в CSV`.
- Тело коммита (если нужно): что и почему, а не «как» — «как» видно из диффа.
- Перед коммитом: `git status`, чтобы не закоммитить мусор (`.env`, `__pycache__`, логи).
- Никогда не используй `git push --force` в чужие ветки и не переписывай историю `main`.

## 4. Конфликты
1. `git status` покажет файлы с конфликтами.
2. Открой файл, найди `<<<<<<<`, `=======`, `>>>>>>>` — оставь правильный вариант,
   объединив смысл обеих сторон, если изменения касаются разных мест.
3. Проверь результат: тесты, `grep_search` по маркерам конфликта (`<<<<<<<` не должно остаться).
4. `git add <файлы>` → `git commit` (сообщение: что объединено).

## 5. Опасные операции (только с подтверждением пользователя)
`git reset --hard`, `git clean -fd`, `git push --force`, `git rebase` опубликованной ветки,
удаление ветки с незапушенными коммитами. Перед ними — `git stash` или создай копию ветки.
