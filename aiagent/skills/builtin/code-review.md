# Код-ревью

## 1. Что смотреть (по приоритету)
1. **Правильность**: неверные условия (`<` вместо `<=`), путаница индексов, потерянные `await`,
   изменяемые аргументы по умолчанию, сравнение `is` со строками/числами.
2. **Безопасность**: SQL-склейка строк, `eval`/`exec` на пользовательских данных,
   путь из внешнего ввода без проверки, секреты в коде и логах, `shell=True` с интерполяцией.
3. **Надёжность**: необработанные исключения в критичных местах, утечки файлов/сокетов
   (нет `with`), бесконечные циклы, отсутствие таймаутов у сетевых вызовов.
4. **Производительность**: запрос в цикле (N+1), квадратичный поиск там, где нужен словарь,
   лишние копии больших структур.
5. **Читаемость**: дублирование, гигантские функции, имена вида `data2`, «мёртвый» код.

## 2. Как оформлять замечание
- Путь и строка: `app/service.py:42`.
- Приоритет: **критично** / **важно** / **мелочь**.
- Суть в одну строку + почему это проблема (что сломается).
- Конкретное предложение по исправлению (короткий фрагмент кода).

## 3. Правила
- Ничего не менять без просьбы: сначала отчёт, затем (по команде) правки.
- Не придираться к стилю, если проект не имеет настроенного линтера и это не влияет на чтение.
- Хвалить осознанные решения полезно, но кратко — отчёт не должен быть «водой».
- Если сомневаешься — проверь факт инструментом (запусти, прочитай вызов), а не догадкой.

## 4. Итог
Сводка: сколько критичных, важных и мелких замечаний; что стоит править первым и почему.
