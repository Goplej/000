# Написание тестов

## 1. Разведка
1. Найди существующие тесты (`glob_search "tests/**/*.py"`) и повторяй их стиль.
2. Пойми фреймворк: pytest / unittest / vitest, какие фикстуры и утилиты уже есть.
3. Определи контракт: что функция обещает, какие побочные эффекты (файлы, сеть, БД).

## 2. Сценарии (минимум)
- **Успех**: обычный корректный вход → ожидаемый результат.
- **Границы**: пустой список, 0, максимальное значение, очень длинная строка, кириллица.
- **Ошибки**: неверный тип, отсутствующий файл, недоступная сеть → правильное исключение/код.
- **Побочные эффекты**: файл создан/удалён, буфер очищен, ресурс закрыт.

## 3. Изоляция
- Внешние вызовы (сеть, API, время) — подменяй (monkeypatch, tmp_path, фикстуры); тесты не должны ходить в интернет.
- Базу данных — в память или временный файл (`tmp_path`).
- Каждый тест независим: порядок запуска не должен влиять на результат.

## 4. Стиль
- Имена: `test_<что>_<условие>_<ожидание>`, например `test_parse_empty_text_returns_error`.
- Одна проверка на смысл; не бойся нескольких `assert` в одном тесте, если это один сценарий.
- Тестовые данные — константы вверху файла или фикстуры, не «магические» значения в середине.

## 5. Прогон
1. `run_shell: pytest -q` — все зелёные.
2. При падении чини либо код, либо тест (но не «подгоняй» тест под баг).
3. Посчитай покрытие, если доступно: `pytest --cov=<пакет> --cov-report=term-missing`.
4. Отчитайся: сколько тестов, что покрыто, какие сценарии остались непокрытыми.
