# AI Agent Studio / C++ — архитектура

> Полностью автономный (offline / self-hosted) ИИ-агент на C++20.
> Никаких облачных API. Мозг — собственный инференс-движок (GGUF/трансформер, квантизация,
> KV-cache) и детерминированный планировщик (GOAP/FSM/графы) как «всегда работающий» режим.

---

## 1. Принципы

| Принцип | Как соблюдается |
|---|---|
| **Offline-first** | Ни одного сетевого вызова в основном цикле. Инференс — локальный (`engine/`). Сеть нужна только веб-интерфейсу и MCP — и то по явной команде. |
| **Никаких облачных API** | В коде нет ни Anthropic, ни OpenAI, ни любых HTTP-клиентов к моделям. Веса берутся из локального файла GGUF. |
| **Zero-dependency** | Только стандартная библиотека C++20 + системные API (Win32 / POSIX). Сторонние библиотеки подключаются опционально и только для ускорения (BLAS/CUDA). |
| **Файлы — крупные подсистемы** | Каждая единица трансляции — законченная подсистема на 2500–18000 строк. Заголовки компактнее (150–1200 строк): держат интерфейс и комментарии, а не реализацию. |
| **Без заглушек** | Любая функция, попавшая в коммит, рабочая и покрыта тестом. Нечего показать — модуль не заводится. |
| **Детерминизм** | При фиксированном seed и одной и той же модели результат воспроизводим. Планировщик вообще детерминирован по построению. |
| **Windows-first, переносимо** | Сборка MSVC и MinGW (цель — Windows), код компилируется и на Linux/macOS (проверяется в CI-сборке g++/clang). |

## 2. Слои

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  app/     — сборка всего: конфиг, реестр инструментов, сессии, агентный цикл  │
├───────────────────────────┬──────────────────────────┬───────────────────────┤
│  ui/                      │  net/                    │  cli/                 │
│  консольный TUI, рендер   │  свой HTTP/1.1, WebSocket│  разбор аргументов    │
│  (markdown, ANSI, таблицы)│  SSE, сокеты, TLS(Vista+)│  команды aia …        │
├───────────────────────────┴──────────────────────────┴───────────────────────┤
│  tools/  — файлы, поиск, патчи, терминал, git, планировщик, память, навыки   │
├──────────────────────────────────────────────────────────────────────────────┤
│  memory/ — эпизодическая, семантическая (векторный индекс), рабочая память    │
├──────────────────────────────────────────────────────────────────────────────┤
│  engine/ — инференс: GGUF → токенизатор → граф трансформера → сэмплер        │
│  plan/   — детерминированный мозг: GOAP-планировщик, FSM, граф знаний        │
├──────────────────────────────────────────────────────────────────────────────┤
│  core/   — строки/Unicode, JSON, статусы, логи, потоки, время, файловая система,
│            математика (тензоры, BLAS-подобные ядра), архивы, крипто-хеши      │
└──────────────────────────────────────────────────────────────────────────────┘
```

Ключевое правило зависимостей: **слой знает только о слоях ниже**. `core` не знает ни о чём,
`engine` знает `core`, `app` знает всех. Циклических зависимостей нет по построению.

## 4. Инференс-движок: как устроен «мозг»

```
model.gguf ──► gguf.cpp ──► (метаданные + тензоры в mmap)
                   │
                   ├─► tokenizer.cpp ──► ids
                   │
                   └─► model.cpp: конфиг слоёв, раскладка весов по бэкендам
                            │
                            └─► graph.cpp: граф вычислений
                                   embedding → [ RMSNorm → QKV → RoPE → KV-cache →
                                   attention (GQA) → O → RMSNorm → SwiGLU MLP ] × N
                                   → final norm → lm_head → logits
                                                    │
                                                    └─► math.cpp: сэмплер
                                                        (temperature, top-k, top-p,
                                                         min-p, repetition/frequency,
                                                         seed → воспроизводимость)
```

Решения и почему:

1. **GGUF, а не свои веса.** Это де-факто стандарт локальных моделей: один файл, метаданные
   внутри, поддержка квантизации. Мы сами разбираем формат (без ggml), что даёт контроль над
   раскладкой и ленивую загрузку через `mmap`.
2. **Своя реализация тензоров и ядер.** Квантизованные типы (`q4_0`, `q4_K`, `q8_0`, `f16`, `bf16`)
   распаковываются в SIMD-ядрах на месте, без материализации полных матриц — иначе 7B-модель
   не влезает в 4 ГБ VRAM / 8 ГБ RAM. Реализация скалярная + AVX2/NEON, с автоматическим выбором
   на старте и бенчмарком.
3. **KV-cache обязателен.** Иначе генерация квадратична. Кэш — непрерывный буфер на слой, с
   поддержкой «скользящего окна» и сдвига при переполнении контекста.
4. **Сэмплер с seed.** Воспроизводимость нужна для тестов и для отладки промптов.
5. **Опционально CUDA/Vulkan.** Интерфейс бэкенда один; CPU-путь всегда доступен и полностью
   самодостаточен (это и есть «offline без сюрпризов»).

## 5. Детерминированный мозг (когда модель не нужна или недоступна)

`plan/goap.cpp` — планировщик с миром-состоянием: предикаты (`file_exists`, `tests_pass`,
`has_key`), операторы с предусловиями и эффектами (`write_file`, `run_tests`, `fix_compile`),
поиск A* по пространству состояний, эвристика из графа знаний. Плюс `plan/fsm.cpp` —
жизненный цикл задачи (понимание → план → исполнение → проверка → отчёт) с ретраями.

Зачем: (а) агент остаётся работоспособным без весов вообще — команды вида «найди файл, покажи
diff, прогони тесты» выполняются мгновенно и предсказуемо; (б) планировщик работает как
«внешний контур» вокруг модели: модель предлагает шаги, GOAP проверяет их достижимость и
порядок.

## 6. Память

| Вид | Где | Что хранит |
|---|---|---|
| Рабочая | `app/agent.cpp` | окно контекста: системный промпт, последние сообщения, результаты инструментов (с усечением) |
| Эпизодическая | `memory/store.cpp` | сессии, события, что уже пробовали и чем закончилось |
| Семантическая | `memory/store.cpp` | факты проекта: стек, команды сборки, соглашения, «грабли» |
| Векторная | `memory/vector.cpp` | эмбеддинги файлов/фрагментов/фактов, гибридный поиск (косинус + BM25) |
| Структурная | `plan/knowledge.cpp` | граф: файлы → символы → зависимости → задачи |

Сжатие контекста: скользящее окно + суммаризация вытесненных сообщений собственной моделью
(или экстрактивным алгоритмом, если модель не загружена).

## 7. Event loop

`core/thread.cpp` даёт пул потоков и task-граф; `app/agent.cpp` строит на нём конвейер
«модель → инструменты → модель» с параллельным исполнением безопасных инструментов (чтение
файлов, поиск, веб-запросы не блокируют друг друга). `net/socket.cpp` — неблокирующий poll-loop
для веб-сервера; UI получает события через канал и рисует их в главном потоке.

## 8. Сборка

```bat
:: Windows (MSVC)
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release -j

:: Windows (MinGW-w64)
cmake -S . -B build-mingw -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build-mingw -j
```

```bash
# Linux/macOS (используется для CI-проверки в песочнице)
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j && ctest --test-dir build --output-on-failure
```

Флаги: `AIA_BUILD_TESTS`, `AIA_ENABLE_AVX2`, `AIA_ENABLE_ASAN`, `AIA_STATIC_RUNTIME` (MSVC),
`AIA_WITH_CUDA` (opt), `AIA_WITH_VULKAN` (opt).
