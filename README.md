# AI Agent Studio — полностью автономный ИИ-агент на C++

> Никаких облачных API. Свой инференс-движок (GGUF/трансформер) + детерминированный
> планировщик (GOAP/FSM), инструменты для файлов и терминала, консольный TUI и
> веб-интерфейс. Всё локально, всё на C++20, без внешних зависимостей.

Текущее состояние: **Шаг 1 завершён** — архитектура, текстовое ядро, сборка, тесты
и рабочий CLI. Ядро уже используется: оно даёт агенту Unicode, diff/патчи, поиск,
хеши, сравнение строк и рендер — то, без чего не будет ни правок файлов, ни
подсветки, ни контекста модели.

---

## Быстрый старт

### Windows (MSVC — как у тебя)

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release -j
build\bin\Release\aia.exe selftest
```

### Windows (MinGW-w64)

```bat
cmake -S . -B build-mingw -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build-mingw -j
```

### Linux / macOS

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Зависимостей нет: только компилятор C++20 и CMake 3.20+. Опционально — CUDA/Vulkan
(флаги `AIA_WITH_CUDA`, `AIA_WITH_VULKAN`) для ускорения инференса на будущих шагах.

## Что уже работает

```bat
aia selftest                 :: 30 внутренних проверок ядра — быстрый тест сборки
aia doctor                   :: окружение, диск, целостность ядра
aia bench                    :: микробенчмарк: SHA-256, CRC32, base64, diff, Левенштейн
aia grep "TODO" src --glob=*.cpp --context=2
aia diff старое.cpp новое.cpp --side
aia patch make a.cpp b.cpp --out=fix.patch
aia patch apply a.cpp fix.patch --write
aia replace main.cpp --find=TODO --with=FIXME --all --write
aia convert файл.txt --to=utf8 --crlf
aia utf8 README.md            :: разбор UTF-8: категории символов, письменности
aia keys README.md --sentences=4     :: ключевые термины и сводка (сжатие контекста)
aia tokens docs/*.md --window=8192   :: оценка токенов и заполнения окна
aia words статья.txt --limit=30      :: частотный словарь и слова-«шум»
aia uniq build.log --limit=10        :: частота строк с гистограммой
aia sort список.txt --unique
aia table данные.csv --delimiter=';'
aia hash aia.exe --check=<sha256>    :: проверка целостности
aia b64 enc "текст" | aia hex dec 4142
aia fuzzy "cnfg" config.cpp main.cpp :: нечёткий поиск
aia slug "Мой Отчёт за 2026 год!"
aia help patch                       :: справка по команде (с подсказкой при опечатке)
```

Все команды рабочие — это собственный инструментарий агента: то, чем он пользуется
при разработке и что потом войдёт в набор инструментов модели.

## Текстовое ядро: `src/core/strings.cpp` (≈5000 строк)

Один файл — одна подсистема. Разделы внутри переиспользуют друг друга (таблицы
опираются на ширину Unicode, diff — на построчный разбор), поэтому файл держится
вместе, а не размазывается по десятку мелких.

| Раздел | Что внутри |
|---|---|
| ASCII и строки | регистр, trim, split/join, replace, pad, indent/dedent, CRLF |
| Числа | разбор (10/16/2/8, разделители разрядов, `1.5 MiB`, `50%`, `1/3`), форматирование, склонения (`5 файлов`) |
| Unicode | UTF-8/UTF-16/CP1251, категории символов, письменности, регистр (латиница, кириллица, греческий), ширина (CJK, эмодзи, комбинирующие знаки), транслитерация, снятие диакритики |
| ANSI | палитра, стили, `strip_ansi`, корректная ширина цветных строк |
| Кодирование | C/JSON/HTML-экранирование, URL, base64 (+base64url), hex, CSV, shell-quoting (POSIX и Windows), пути (включая `..` и защиту от выхода за каталог) |
| Хеши | SHA-256 (проверено на эталонных векторах), CRC32, FNV-1a 64, случайные токены |
| Сравнение | Левенштейн, Дамерау, Джаро-Винклер, LCS, fuzzy-скор с подсветкой, natural sort, wildcard (`*`, `?`, `[...]`, `**`) |
| Текст и рендер | перенос по колонкам, таблицы, рамки, прогресс-бары, Markdown → ANSI, шаблоны `{{имя}}`, статистика текста, оценка токенов, ключевые термины и сводка |
| Diff и патчи | LCS по Хиршбергу (строки, слова, символы), unified diff с хунками, применение патча с понятными ошибками, мягкая замена фрагмента (учитывает отступы) |

Важное решение: **сравнение строк работает по кодпоинтам, а не по байтам**. Иначе
перестановка двух кириллических букв («привет» → «пирвет») считалась бы за четыре
правки вместо одной, и fuzzy-поиск по русским именам файлов ломался бы.

## Архитектура (план, 38 крупных единиц)

Полная карта — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Кратко:

```
app/    сборка всего: конфиг, сессии, агентный цикл, хуки, MCP
ui/     консольный TUI, рендер Markdown/diff, веб-интерфейс
net/    свой HTTP/1.1, SSE, WebSocket (для веб-UI и MCP)
tools/  файлы, поиск, патчи, терминал, git, планировщик, навыки
memory/ эпизодическая, семантическая и векторная память
engine/ инференс: GGUF → токенизатор → граф трансформера → сэмплер
plan/   детерминированный мозг: GOAP, FSM, граф знаний
core/   строки, числа, файлы, логи, тензоры, потоки
```

Правило зависимостей: **слой знает только о слоях ниже**. `core` не знает ни о чём,
`app` знает всех. Циклических зависимостей нет по построению.

| Шаг | Что делаем | Статус |
|---|---|---|
| 1 | Архитектура, текстовое ядро, сборка, тесты, CLI | **готово** |
| 2 | Сетевой слой: сокеты, HTTP-сервер, SSE, WebSocket | следующий |
| 3 | Инференс: GGUF → токенизатор → тензоры → граф → модель → сэмплер | |
| 4 | Память: хранилище, векторный индекс, сжатие контекста | |
| 5 | Event loop: пул потоков, task-граф, каналы, таймеры | |
| 6 | Инструменты: файлы, поиск, shell, патчи, git, планировщик | |
| 7 | Интерфейсы: консольный TUI и веб-интерфейс | |
| 8 | Приложение: конфиг, сессии, агентный цикл, хуки, MCP | |
| 9 | Качество: тесты по всем подсистемам, бенчмарки, документация | |

## Тесты

```bash
ctest --test-dir build --output-on-failure
```

- `aia_tests` — 40 тестов текстового ядра (по разделам: строки, числа, Unicode,
  кодировки, хеши, сравнение, рендер, diff) — свой мини-фреймворк, без зависимостей.
- `core_selftest` — 30 инвариантов через CLI: быстрый способ убедиться, что сборка
  корректна на новой платформе.
- `cli_smoke` — запуск бинарника.

Тесты не «для галочки»: на первом прогоне они нашли 14 настоящих ошибок — от
неверной базы FNV-1a до лишней пустой строки при применении патча и сравнения
кириллицы по байтам. Все они исправлены, а соответствующие проверки остались в
наборе, чтобы не вернулись.

## Требования к коду

- **C++20**, без внешних зависимостей; исключения — только на границе процесса,
  внутри всё через `Status`/`Result<T>` (см. `src/core/status.hpp`).
- **Ошибки — значения**: `Status{код, сообщение, контекст}` с русским описанием и
  подсказкой, что делать.
- **Файл — законченная подсистема** (2500–18000 строк), а не «удобный для чтения
  кусочек». Заголовки — компактные: интерфейс и решение, без реализации.
- **Каждая функция рабочая**: попало в сборку — либо используется, либо покрыто
  тестом. Заглушек и `// TODO: implement later` в проекте нет.
- Строгие предупреждения: `/W4 /permissive-` (MSVC) и `-Wall -Wextra -Wpedantic
  -Wshadow -Wold-style-cast …` (GCC/Clang). Сборка должна быть чистой.

```bash
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DAIA_WITH_ASAN=ON -DAIA_WITH_UBSAN=ON
```
